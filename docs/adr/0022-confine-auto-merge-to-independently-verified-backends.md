# Confine Auto-Merge to Independently Verified Backends

Auto-merge is enabled per Loop rather than per project, because a Loop removing an unused import and a Loop reworking error handling carry risks that differ by orders of magnitude, and one project-wide switch would let the first one's convenience vouch for the second. Arming requires every condition to hold at publication time: the change is low risk, the independent review approved it, the pull request is not a draft, its Validation Gates passed, the repository allows auto-merge, the project declares at least one required workflow, and the base branch is protected. The verdict records every unmet condition rather than returning a boolean, because auto-merge is the one path where a model's output reaches the default branch unread and the reason it did — or did not — is part of the decision.

A backend whose Verify stage cannot run without the model credential is not an independent check of that model's work. Such a backend refuses a Loop that asks to merge unattended, before any branch is pushed, instead of quietly opening an ordinary pull request: a configuration that says merge and behaves like propose is a configuration that lies to whoever reads it next. Today only the hosted backend qualifies, because only there does Verify run on a separate runner holding no model credential.
